System Architecture

Six folders. One pipeline.

Every lead enters through the orchestrator and flows to the right specialist. Structured handoff envelopes ensure nothing is lost between steps.

Lead flow — all three intake paths
00_orchestrator
Reads input → identifies source + urgency → formats handoff envelope → routes to first specialist. Opus 4.7.
▼
01_lead_qualifier
Scores on 4 dimensions (timeline, budget, motivation, responsiveness). Creates case file. Sets next-action directive. Routes by score.
▼
02_property_research
Neighbourhood briefs, CMAs, showing prep, listing analysis.
03_client_communication
Drafts in each agent's voice. Never sends autonomously.
04_transaction_coordinator
Deadline tracking. Option period alerts. TREC checklist.
05_nurture_coordinator
Long-game touches for not-ready leads. Graduation detection.
▼
_config/
team.md · team-standards.md · buyer/seller checklists
_shared/
voices/ · cases/ — loaded by every specialist at runtime

Three intake paths: Path A — platform emails auto-routed from leads@ inbox via hourly Cloud Routine. Path B — personal inboxes filtered and forwarded to leads@. Path C — manual entry in Claude Code for walk-ins, calls, and open house sign-ins.

What makes this different

    
Built for boutique teams, not enterprise platforms

    
No SaaS subscription. No monthly seat fee. Runs entirely inside Claude.


    

      

        
🎙️

        
Agent voice profiles

        
Every draft matches the agent who sends it. Marcus texts differently than Diana emails. The system knows the difference.

      

      

        
⚡

        
Three intake paths

        
Platform emails, forwarded inbox emails, and manual walk-in entries all produce identical output: case file + draft + pipeline row.

      

      

        
📋

        
TREC-native transactions

        
Texas forms, option period alerts, earnest money deadlines — built around how Austin real estate actually works.

      

      

        
🌱

        
05_nurture_coordinator

        
The specialist nobody else built. Keeps not-ready leads alive for 12–24 months with value-first touches. Detects graduation signals automatically.

      

      

        
🔁

        
Hourly Cloud Routine

        
Runs automatically on Anthropic servers. Reads leads@, processes every new email, writes drafted responses to agent Gmail drafts. No one has to start it.

      

      

        
🧠

        
Model routing at L0

        
Orchestrator runs on Opus 4.7 for reasoning. Processing specialists run on Sonnet 4.6 for speed. Defined in CLAUDE.md — no config files, no API calls.

      

    

  







  

    
Quick start

    
Up and running in 30 minutes

    
Claude guides you through every step. You do not need to configure anything manually.


    

      

        
1

        

          
Clone the repo

          
Download or clone diana-calloway-real-estate-ai to your computer. Open it in Claude Code as your project folder.

        

      

      

        
2

        

          
Start onboarding

          
Type start onboarding in Claude Code. Claude reads the CLAUDE.md and walks you through 6 steps: Gmail connection, shared inbox, Drive setup, team config, Cloud Routine creation, and a test run.

        

      

      

        
3

        

          
Customise your team

          
Claude asks 4 questions and writes your team config automatically. Update _shared/voices/ with your agents' actual names and communication styles.

        

      

      

        
4

        

          
Send a test lead

          
Forward a test email to your leads@ inbox. Claude processes it, creates a case file, and writes a draft response into the assigned agent's Gmail drafts. When it works, you're live.
